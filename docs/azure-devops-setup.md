# Azure DevOps Artifact Mirroring Setup

This guide explains how to configure Azure DevOps artifact mirroring in the n8n workflows. When configured, artifacts generated by the pipelines will be pushed to both GitHub AND Azure DevOps in parallel.

## Overview

The following workflows support Azure DevOps mirroring:
- Business Analysis Pipeline
- Architecture Pipeline
- Solution Architecture Pipeline
- Software Delivery Pipeline
- Project Management Pipeline
- Risk Assessment Pipeline
- Test Strategy Pipeline
- Quality and Compliance Pipeline
- QA and Compliance Pipeline

## Prerequisites

1. An Azure DevOps organization
2. A project in your Azure DevOps organization
3. A Git repository in your Azure DevOps project
4. A Personal Access Token (PAT) with Code (Read & Write) permissions

## Configuration Steps

### Step 1: Create Azure DevOps Personal Access Token (PAT)

1. Go to [Azure DevOps](https://dev.azure.com/) and sign in
2. Click on your profile icon → Personal access tokens
3. Click "New Token"
4. Configure the token:
   - Name: `n8n-artifact-push` (or any name you prefer)
   - Organization: Select your organization
   - Expiration: Set as needed (recommend 1 year max)
   - Scopes: Custom defined → Code (Read & Write)
5. Click "Create" and **copy the token** (you won't see it again)

### Step 2: Configure Environment Variables

Add the following to your `.env` file:

```bash
# Azure DevOps Configuration
AZURE_DEVOPS_ORG=your-organization
AZURE_DEVOPS_PROJECT=your-project
AZURE_DEVOPS_REPO=your-repository
AZURE_DEVOPS_PAT=your-personal-access-token
```

For example:
```bash
AZURE_DEVOPS_ORG=socrateshlapolosa
AZURE_DEVOPS_PROJECT=AI Exploration
AZURE_DEVOPS_REPO=architecture-artifacts
AZURE_DEVOPS_PAT=xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
```

### Step 3: Create HTTP Basic Auth Credential in n8n

1. Open n8n at http://localhost:5678
2. Go to **Settings** → **Credentials**
3. Click **Add Credential** → **HTTP Basic Auth**
4. Configure:
   - **Credential Name**: `Azure DevOps PAT`
   - **User**: Leave empty (or use any string like `user`)
   - **Password**: Paste your Azure DevOps PAT
5. Click **Save**
6. **Copy the credential ID** from the URL (e.g., `abc123xyz`)

### Step 4: Update Workflow Files with Credential ID

The workflow files contain a placeholder credential ID `AZURE_DEVOPS_PAT_CREDENTIAL_ID`. You need to replace this with your actual credential ID.

Run this command from the project root (replace `YOUR_CREDENTIAL_ID` with your actual ID):

```bash
# Replace placeholder with actual credential ID
find n8n/backup/workflows -name "*Pipeline*.json" -exec sed -i '' 's/AZURE_DEVOPS_PAT_CREDENTIAL_ID/YOUR_CREDENTIAL_ID/g' {} \;
```

For example:
```bash
find n8n/backup/workflows -name "*Pipeline*.json" -exec sed -i '' 's/AZURE_DEVOPS_PAT_CREDENTIAL_ID/abc123xyz/g' {} \;
```

### Step 5: Import/Restart Workflows

If workflows are already imported in n8n, you'll need to reimport them:

1. Go to **Workflows** in n8n
2. For each pipeline workflow:
   - Delete the existing workflow (or deactivate it)
   - Import the updated version from `n8n/backup/workflows/`

Alternatively, restart the n8n container to pick up the updated files:
```bash
docker compose -p localai restart n8n
```

## How It Works

### Workflow Architecture

When Azure DevOps is configured:

```
[Build Git Script]
       │
       ├──────────────────────→ [SSH: Commit to GitHub]
       │                                    │
       └──→ [If: Azure Enabled?]           │
                   │                        │
           yes ←───┴───→ no                 │
            │             │                 │
     [Get Azure Repo]  [NoOp]              │
            │             │                 │
     [Build Payload]      │                 │
            │             │                 │
     [Push to Azure]      │                 │
            │             │                 │
            └─────────────┴─────────────────┘
                          │
                   [Merge Results]
                          │
                   [Update Job Status]
```

### Conditional Execution

The Azure DevOps path only executes if `AZURE_DEVOPS_ORG` environment variable is set and non-empty. If not configured:
- GitHub push works normally
- Azure DevOps push is skipped silently

## Troubleshooting

### Azure Push Fails with 401 Unauthorized

- Verify your PAT has not expired
- Ensure the PAT has Code (Read & Write) permissions
- Check the PAT is correctly entered in the HTTP Basic Auth credential

### Azure Push Fails with 404 Not Found

- Verify the organization, project, and repository names are correct
- Check for URL encoding issues with spaces (use `%20` for spaces)
- Ensure the repository exists in your Azure DevOps project

### Branch Already Exists Error

The push payload uses `oldObjectId` of all zeros for new branches. If the branch already exists, you may need to:
1. Delete the branch in Azure DevOps
2. Or modify the workflow to fetch the current branch commit ID first

### Artifacts Not Appearing in Azure DevOps

1. Check the workflow execution logs in n8n
2. Verify the "If: Azure Enabled" node is taking the true path
3. Check the "Push to Azure DevOps" node output for errors

## API Reference

The workflows use the Azure DevOps REST API:

- **Get Repository**: `GET https://dev.azure.com/{org}/{project}/_apis/git/repositories/{repo}?api-version=7.1`
- **Push Commits**: `POST https://dev.azure.com/{org}/{project}/_apis/git/repositories/{repo}/pushes?api-version=7.1`

See [Azure DevOps Git API documentation](https://docs.microsoft.com/en-us/rest/api/azure/devops/git/) for more details.

## Disabling Azure DevOps Mirroring

To disable Azure DevOps mirroring while keeping GitHub working:

1. Comment out or remove the Azure DevOps environment variables from `.env`:
   ```bash
   # AZURE_DEVOPS_ORG=your-organization
   # AZURE_DEVOPS_PROJECT=your-project
   # AZURE_DEVOPS_REPO=your-repository
   # AZURE_DEVOPS_PAT=your-token
   ```

2. Restart n8n:
   ```bash
   docker compose -p localai restart n8n
   ```

The workflows will continue to push to GitHub, and the Azure DevOps path will be skipped automatically.
